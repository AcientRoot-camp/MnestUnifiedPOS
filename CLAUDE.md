# Project Rules for Claude

These rules apply to every task in this project.

## 1. Code must be commented

- Add clear, meaningful comments to all code you write or modify.
- Every file gets a short header comment explaining its purpose.
- Every function, class, component, and module gets a comment describing what it does, its inputs, and its outputs.
- Comment non-obvious logic, business rules, and workarounds, explaining the "why" and not only the "what".
- Keep comments accurate: update or remove them when the code changes.

## 2. Git and version control

- Do NOT commit or push to GitHub or GitLab unless the user explicitly asks.
- When asked to commit or open a PR/MR, do NOT add any co-author or co-contributor attribution. This means no `Co-Authored-By` trailers and no "Generated with Claude Code" lines in commit messages, PR descriptions, or MR descriptions.
- Commit messages and PR/MR descriptions should read as written solely by the user.

## 3. Required legal pages

The system must always include these pages, linked from the footer or navigation and reachable from sign-up and checkout flows:

- **Privacy Policy**: what personal data is collected, why, how it is stored and shared, retention, and user rights.
- **Cookie Policy**: which cookies and similar technologies are used, their purpose, and how to manage them. Include a cookie consent banner or preferences control where required.
- **Legal pages**: Terms of Service (or Terms and Conditions) and any other legal notices that apply, such as a refund policy or disclaimer.

If any of these pages is missing when you work on the system, add it or flag it to the user. Use clearly marked placeholder text for business-specific details, and recommend legal review before launch.
